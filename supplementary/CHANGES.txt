Rationale:
1. certificates/CertMajV2/r4_majorant_arb.py had an absolute Windows path with the
   writer's username hardcoded as the location of its input .npy file. Fixed to a
   path relative to the script's own file location, since the data file ships

   absolute Windows checkout path for the zeta-23-lean repository if the
   LEANRUN_TREE environment variable was not set. A relative path is not meaningful
   here (the Lean repository is not part of this archive and may be checked out
   anywhere), so the default was removed and the scripts now fail with a clear
   message asking the user to set LEANRUN_TREE, instead of silently guessing an
   absolute path that does not exist on another machine. See VERIFY.md.

Known caveat, not fixed here (out of scope: it is a directory-depth assumption, not a
username leak). run_replay.sh line 29 (`TOOLS="$(cd "$R/../../../lean_tools" && pwd)"`)
and run_pools.py line 37-38 (`HEAVY_LEANRUN`) assume the driver still lives 4 levels
under the project root, as it did in the working tree,
and that a sibling `lean_tools/leanrun.sh` exists. Neither holds once this folder is
staged or archived on its own. `lean_tools/` is this project's own internal Lean
harness and is not part of the supplementary archive. A third party who wants to run
the two-pool driver as-is should either restore the original relative depth or point
TOOLS/HEAVY_LEANRUN at their own `lake env lean` wrapper; see VERIFY.md, which gives
the two-command "quick check" path that does not depend on this driver at all.

12. CertS8 run manifest (new: certificates/CertS8/s8_manifest.py). mkinit.sh writes
    runs/<TAG>/run_manifest.json and every round updates it: the objective of the run and its
    sha256 (item 13); the root (init.log: a fresh start that stopped at its box budget;
    init.ckpt: sha256, boxes, processed; sha256 of the sorted rows of its stack); for every
    round N, its shards as written (name, sha256, boxes), its parents and the sha256 of the
    sorted rows of their union, and, once closed, each shard's outcome (certified: its log
    and sha256; left: its log and the checkpoint it left, sha256 and boxes). The parents of
    round R+1 are exactly the checkpoints left in round R, or after a change of N all shards
    of round R. A copy of the manifest as it stood when each round opened is kept in
    runs/<TAG>/manifests/. Before any round or re-shard it refuses (exit status 4): a folder

    complete run; a round other than the current one; a missing shard or one whose sha256

    lineage copy that disagrees. After a round it accepts a shard as certified only if its
    process exited 0, its log ends with {'ok': True, and names the objective and the sha256

    time limit (124) with a checkpoint of the objective. 'ok': False marks the run failed for
